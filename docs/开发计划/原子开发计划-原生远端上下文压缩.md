## 固定接口与数据契约

以下名称是计划建议的稳定语义。若仓库现有命名要求调整，可改名但不得改变职责；必须在执行记录写明名称偏差。

### Provider Context Envelope

`packages/ai/src/types.ts` 增加只包含纯 JSON 的 Provider Context：

```ts
type JsonPrimitive = string | number | boolean | null;
type JsonValue = JsonPrimitive | { readonly [key: string]: JsonValue } | readonly JsonValue[];

interface ProviderContextBinding {
  readonly provider: string;
  readonly api: Api;
  readonly model: string;
  readonly endpoint: string;
  readonly format: "openai-responses-compaction";
  readonly protocol:
    | "openai-responses-compact"
    | "openai-codex-remote-v2"
    | "openai-codex-compact-legacy";
  readonly credentialScopeHash: string;
}

interface ProviderContextEnvelope {
  readonly format: "openai-responses-compaction";
  readonly version: 1;
  readonly binding: ProviderContextBinding;
  readonly items: readonly JsonValue[];
}
```

约束：

- `items` 只能保存经过 Runtime Validation 的 canonical JSON Item；不得保存 `compaction_trigger`。
- Provider → Agent、Agent Setter/Getter/Snapshot → Request、Session Parse/Build 四类边界都必须 Validate 并 Deep Clone；不能只复制顶层 Array。
- `credentialScopeHash` 不得进入 TUI、RPC、Extension Event、HTML、普通 Log 或 Error。
- API Key Fingerprint 为 `SHA-256("api-key:" + fullKey)`；ChatGPT OAuth 为 `SHA-256("chatgpt-account:" + chatgpt_account_id + ":" + credentialSource)`。不得 Hash 短期 Access Token；无法提取稳定 Subject 时 Native Capability 不可用。
- Endpoint 是 Adapter 实际解析并发网的稳定 URL/Protocol Identity；是否包含语义 Query 由 Adapter 决定，但不得包含 Token、Header、Fragment、凭据或其他请求秘密。
- `credentialScopeHash` 只能由 `Models.applyAuth()` 的内部 Effective Auth Resolution 生成，不能出现在公开 Compact Options 或由调用方传入。API Key 必须对完整已解析 Key 做 `SHA-256("api-key:" + fullKey)`；OAuth 只接受 Credential 中的稳定 Subject（优先 `chatgpt_account_id`/`accountId`）与稳定 Provider Source，缺少 Subject 时返回 Unsupported。
- Effective Auth Resolution 通过非枚举内部元数据把 Scope Hash 传给 Native Request；不能把 Scope Hash 添加到现有 `AuthResult` 可枚举字段，不能写入普通 Error、日志或公开 DTO。
- Native Error 是独立的 Sanitized Error 类型，只允许固定 Error Code 和固定安全消息；不得保留 `cause`、Request/Response Body、Canonical Item、Endpoint、Scope Hash 或未经净化的 Provider Message。
- Runtime JSON Validator 必须拒绝 Date、Map、Set、TypedArray、NaN、Infinity、稀疏数组、Symbol、Accessor、非枚举字段和自定义 Prototype；通过后执行深复制和深冻结。所有 Provider→Models、Models→Provider、Lazy 与 Capability Result 边界都必须重新验证或复制。

### Provider Capability

- `ProviderStreams`、`Provider`、`Models` 与后续 `ModelRuntime` 提供可选 `compact` 和 `canConsumeProviderContext`；两者必须成对存在，缺少任一项即 Unsupported。
- `Models.compact(model, context, options)` 与 `Models.canConsumeProviderContext(model, providerContext, options)` 是唯一公开的 Native 编排入口。两者都必须先执行同一个 `NativeCompactionPreflight`：解析 Effective Auth、取得 Adapter 提供的 Endpoint Identity、计算 Binding、确认 Capability 成对存在，再创建内部 branded Request；公开 Options 不包含 Binding、Scope Hash、Provider Context 或内部品牌。
- Provider/ProviderStreams 的 Native 方法只接受由 Models 工厂创建并登记在私有 `WeakSet` 中的 Request；createProvider、Lazy 和 Compat 对未登记 Request 一律返回 Sanitized Unsupported。Provider 直接调用不能绕过 Models 的 Auth/Binding Preflight。
- Endpoint Identity 由具体 Adapter 提供 `resolveNativeCompactionEndpoint(model, resolvedOptions)`，必须复用该 Adapter 普通请求实际使用的 URL/协议解析函数。Resolver 返回的 Identity 是已经考虑语义 Query、租户路由和协议版本的稳定字符串；Models 只校验其为不含凭据、Fragment 和控制字符的绝对 URL/Identity，不自行删除 Query 或改写协议。Resolver 无法安全给出 Identity 时返回 Unsupported。不得在基础契约中复制 Codex/Azure/Cloudflare 的 Adapter 规则。
- OAuth 稳定 Subject 必须来自 Provider-owned `OAuthAuth.getStableSubject(credential)`；不得从任意扩展字段或短期 Access Token 猜测。Credential Source 固定为 `Provider.id`，Subject 缺失、非非空字符串或刷新后不稳定时返回 Unsupported。
- 未声明 Capability 的 Provider/Custom StreamFn 必须明确返回 Unsupported，不得忽略 `providerContext` 后继续发网。
- `canConsumeProviderContext` 必须使用本次请求的 Effective Model、Resolved Endpoint 与已解析 Auth；Model Switch 检查和每次普通 Stream/Native Compact 发网前必须复用同一 Preflight。
- Lazy API 默认完全不暴露 Capability；只有调用方显式开启 Native Compaction 代理且底层模块通过成对 Capability 校验时才提供方法。普通 Stream 不得因为 Lazy 包装而加载或触发 Native Capability。
- Compat Registry 可以内部识别可选字段，但旧 `ApiProvider` 与公共 `compat` 函数不得直接暴露 Native Capability；任何没有 Effective Binding 的 Compat Native 调用必须 Unsupported，不能绕过 `Models.applyAuth()`。

### Session Entry

- 保留现有 `type: "compaction"` 作为 Local Compaction，不增加模糊 Strategy 字段，不修改旧 Entry。
- 新增独立 `type: "remote_compaction"`。它至少保存 Entry ID、Parent ID、Timestamp、Operation ID、Sanitized Summary、Self `firstKeptEntryId`、Tokens Before、Usage、Provider Context Envelope 与内部 Metadata。
- Session Version 升为 4；v3 → v4 Migration 只更新 Header Version，不改写现有 Compaction Entry 的业务字段。
- `buildSessionContext` 在最新 Active Entry 是 Remote 时返回 Provider Context 和该 Entry 之后的新 Messages；不把 Sanitized Summary 送给 LLM。
- `buildPortableRawContext` 沿当前 Leaf Ancestry 构造扁平原始语义 Entry，排除所有 Local/Remote Compaction、Provider Context、Trigger、管理 Entry、Sibling 与指定 Overflow Error Entry。

### Compaction Metadata DTO

所有自动展示边界只允许使用同一个 Allowlist DTO：

- `attemptId`、`operationId`。
- `reason: manual | threshold | overflow`。
- `requestedStrategy: local | remote | auto`。
- `effectiveStrategy: local | remote`。
- `protocol`、`provider`、`model`。
- `tokensBefore`、`estimatedTokensAfter`、可公开 Usage。
- `fallbackCode` 或 `errorCode`，值只能来自内部 Sanitized Enum/Union。
- `experimental: true`，直到真实 R1 Gate 完成。

DTO 不得包含 `providerContext`、`items`、`encrypted_content`、Credential Hash、Resolved Endpoint、Provider Response Body、Request Body 或未经净化的 Provider Error Message。

### Compaction Attempt FSM

固定顺序：

1. 解析 Requested Strategy，生成 Attempt/Operation/Entry ID，冻结 Branch Head。
2. 从当前 Ancestry 构建 Portable Preparation；Overflow 时排除 Trigger Assistant Entry。
3. 调用 `session_before_compact`。
4. 处理 Hook：所有策略允许 Cancel；显式 Remote 收到 Custom Result 时失败；Local/Auto 可接受 Custom Local Result。
5. 执行 Capability/Binding/Capacity Preflight。
6. 执行 Remote 或 Local；Auto 每 Attempt 最多一次 Remote 与一次 Local Fallback。
7. Adapter 结果完整验证；再次确认 Branch Head 未变化且未 Abort。
8. 进入 Append Phase。此后禁止 Fallback 或 Reissue。
9. 以 Operation ID 幂等 Append。Append 抛错时 Reload Session 并查询 Operation ID：存在即视为 Committed；不存在则返回 Indeterminate/Failed，禁止自动重试。
10. 从已提交 Session 重建 Context，通过 Agent 的原子 `replaceContext()` 一次替换 Messages 与 Provider Context。
11. 发出 Sanitized Post Event；再由现有 Queue 逻辑 Flush 消息。

“Commit 前零状态变化”仅指 Compaction-owned Session/Agent State。Extension Hook 可能有第三方副作用，系统不承诺回滚；Hook 后必须重验 Frozen Branch Head，并在文档中要求 Hook 保持只读。

### Native Request/Result/Error Allowlist

- `NativeCompactionPublicOptions` 只允许现有请求控制字段（如 signal、timeout、headers、env、Provider Adapter 选项），显式排除 `binding`、`credentialScopeHash`、`providerContext`、`requestId` 和内部品牌。
- `NativeCompactionProviderRequest` 只包含：有效 Model、Canonical Context、Resolved Provider Options、标准化 Binding 和可选的已验证 Provider Context；额外键、未冻结对象和未登记品牌均拒绝。
- `NativeCompactionResult` 只允许 `providerContext` 和可公开 `usage` 两个顶层键；Envelope 只允许 `format/version/protocol/binding/items`；Binding 只允许 `provider/api/model/endpoint/format/protocol/credentialScopeHash`；Usage 只允许固定数值字段；任何额外键、空字符串、错误版本、错误协议或非纯 JSON Item 都返回 `invalid_context`/`protocol`。
- `canConsumeProviderContext` 只返回布尔值；输入验证失败或 Provider 抛错时由 Models 返回 Sanitized Native Error，不把 Provider 返回值、异常文本或 Context 原文写入 Error。普通 Stream 在没有 `providerContext` 时保持旧路径；存在非空 `providerContext` 但没有 Consumer 时必须在任何 Fetch 前返回 Sanitized Unsupported。
- Native Error Code 到安全 Message 必须是固定表：`unsupported`、`invalid_context`、`binding_mismatch`、`capacity`、`protocol`、`aborted`；Error 自身没有 `cause`、原始异常字段或自定义序列化字段。

## 策略与失败语义

| 请求 | Native 可用 | Native 结果 | 行为 |
|---|---:|---|---|
| `local` | 任意 | 不适用 | 只执行 Portable Local |
| `remote` | 否 | 不适用 | 失败；不 Fallback |
| `remote` | 是 | 任意失败 | 失败；不 Fallback |
| `auto` | 否 | 不适用 | 执行 Portable Local，记录 Unsupported |
| `auto` | 是 | 成功 | 提交 Remote |
| `auto` | 是 | 非 Abort、非 Stale、Append 前失败 | 最多一次 Portable Local Fallback |
| `auto` | 是 | Abort、Stale 或已进入 Append Phase | 不 Fallback |

Codex V2 → Legacy 不是 Local Fallback。只有 HTTP Status 属于 400/404/422，且结构化 `code/message/param` 同时明确表达 “unsupported/unknown feature” 和 `compaction_trigger` 或 `remote_compaction_v2` 时，才允许尝试 Legacy。Bare 404、`model_not_found`、401/403、429、5xx、Network、Timeout、Malformed JSON、SSE Early Close 或 0/2 Compaction Item 均不得尝试 Legacy。真实 R1 发现新 Error Shape 时只能新增精确 Fixture 与 Allowlist，不得放宽为 Status-only。
