## 固定接口与数据契约

以下名称是计划建议的稳定语义。若仓库现有命名要求调整，可改名但不得改变职责；必须在执行记录写明名称偏差。

### Provider Context Envelope

`packages/ai/src/types.ts` 增加只包含纯 JSON 的 Provider Context：

```ts
type JsonPrimitive = string | number | boolean | null;
type JsonValue = JsonPrimitive | { readonly [key: string]: JsonValue } | readonly JsonValue[];

interface ProviderContextBinding {
  readonly provider: string;
  readonly api: Api;
  readonly model: string;
  readonly endpoint: string;
  readonly format: "openai-responses-compaction";
  readonly protocol:
    | "openai-responses-compact"
    | "openai-codex-remote-v2"
    | "openai-codex-compact-legacy";
  readonly credentialScopeHash: string;
}

interface ProviderContextEnvelope {
  readonly format: "openai-responses-compaction";
  readonly version: 1;
  readonly binding: ProviderContextBinding;
  readonly items: readonly JsonValue[];
}
```

约束：

- `items` 只能保存经过 Runtime Validation 的 canonical JSON Item；不得保存 `compaction_trigger`。
- Provider → Agent、Agent Setter/Getter/Snapshot → Request、Session Parse/Build 四类边界都必须 Validate 并 Deep Clone；不能只复制顶层 Array。
- `credentialScopeHash` 不得进入 TUI、RPC、Extension Event、HTML、普通 Log 或 Error。
- API Key Fingerprint 为 `SHA-256("api-key:" + fullKey)`；ChatGPT OAuth 为 `SHA-256("chatgpt-account:" + chatgpt_account_id + ":" + credentialSource)`。不得 Hash 短期 Access Token；无法提取稳定 Subject 时 Native Capability 不可用。
- Endpoint 是 Adapter 实际解析并发网的稳定 URL/Protocol Identity；是否包含语义 Query 由 Adapter 决定，但不得包含 Token、Header、Fragment、凭据或其他请求秘密。
- `credentialScopeHash` 只能由 `Models.applyAuth()` 的内部 Effective Auth Resolution 生成，不能出现在公开 Compact Options 或由调用方传入。API Key 必须对完整已解析 Key 做 `SHA-256("api-key:" + fullKey)`；OAuth 只接受 Credential 中的稳定 Subject（优先 `chatgpt_account_id`/`accountId`）与稳定 Provider Source，缺少 Subject 时返回 Unsupported。
- Effective Auth Resolution 通过非枚举内部元数据把 Scope Hash 传给 Native Request；不能把 Scope Hash 添加到现有 `AuthResult` 可枚举字段，不能写入普通 Error、日志或公开 DTO。
- Native Error 是独立的 Sanitized Error 类型，只允许固定 Error Code 和固定安全消息；不得保留 `cause`、Request/Response Body、Canonical Item、Endpoint、Scope Hash 或未经净化的 Provider Message。
- Runtime JSON Validator 必须拒绝 Date、Map、Set、TypedArray、NaN、Infinity、稀疏数组、Symbol、Accessor、非枚举字段和自定义 Prototype；通过后执行深复制和深冻结。所有 Provider→Models、Models→Provider、Lazy 与 Capability Result 边界都必须重新验证或复制。
- 本地 Session 的 Append-only Raw Ancestry 是会话事实来源；Remote/Local Compaction 只能替换运行中的 Active Context，不能删除、隐藏或覆盖原始 Message/Tool/Custom Entry。`providerContext` 是绑定到特定 Provider/API/Model/Endpoint/Credential Scope 的可失效派生数据，切换账号、Key、模型或 Endpoint 只能使其失效并触发 Portable Recovery，不能让本地对话消失。

### Provider Capability

- `ProviderStreams`、`Provider`、`Models` 与后续 `ModelRuntime` 提供可选 `compact`、`canConsumeProviderContext` 和 `resolveNativeCompactionEndpoint`；三件套必须同时存在，缺少任一项即 Unsupported。
- `Models.compact(model, context, options)` 与 `Models.canConsumeProviderContext(model, providerContext, options)` 是唯一公开的 Native 编排入口。两者都必须先执行同一个 `NativeCompactionPreflight`：解析 Effective Auth、取得 Adapter 提供的 Endpoint Identity、计算 Binding、确认 Capability 三件套同时存在，再创建内部 branded Request；公开 Options 不包含 Binding、Scope Hash、Provider Context 或内部品牌。
- `openai-responses` 与 `openai-codex-responses` 分别拥有独立 Native Capability：前者只处理 API Key/OpenAI Public 路径，后者只处理 ChatGPT Account/Codex Backend 路径。不得把两者合成一个 Adapter、自动互换认证或共享开放 Options；Models 只按 `model.api` 分派到现有 Adapter。完全相同的纯校验 Helper 可以内部复用，但 Endpoint、Auth、Protocol 和逐 API 选项仍由各自 Adapter 决定。
- Provider/ProviderStreams 的 Native 方法只接受由 Models 工厂创建并登记在私有 `WeakSet` 中的 Request；createProvider、Lazy 和 Compat 对未登记 Request 一律返回 Sanitized Unsupported。Provider 直接调用不能绕过 Models 的 Auth/Binding Preflight。
- Endpoint Identity 由具体 Adapter 提供 `resolveNativeCompactionEndpoint(model, resolvedOptions)`，必须复用该 Adapter 普通请求实际使用的 URL/协议解析函数。Resolver 返回的 Identity 是已经考虑语义 Query、租户路由和协议版本的稳定字符串；Models 只校验其为不含凭据、Fragment 和控制字符的绝对 URL/Identity，不自行删除 Query 或改写协议。Resolver 无法安全给出 Identity 时返回 Unsupported。不得在基础契约中复制 Codex/Azure/Cloudflare 的 Adapter 规则。
- OAuth 稳定 Subject 必须来自 Provider-owned `OAuthAuth.getStableSubject(credential)`；不得从任意扩展字段或短期 Access Token 猜测。Credential Source 固定为 `Provider.id`，Subject 缺失、非非空字符串或刷新后不稳定时返回 Unsupported。
- 未声明 Capability 的 Provider/Custom StreamFn 必须明确返回 Unsupported，不得忽略 `providerContext` 后继续发网。
- `canConsumeProviderContext` 必须使用本次请求的 Effective Model、Resolved Endpoint 与已解析 Auth；Model Switch 检查和每次普通 Stream/Native Compact 发网前必须复用同一 Preflight。
- Lazy API 默认完全不暴露 Capability；只有调用方显式开启 Native Compaction 代理且底层模块通过成对 Capability 校验时才提供方法。普通 Stream 不得因为 Lazy 包装而加载或触发 Native Capability。
- Compat Registry 可以内部识别可选字段，但旧 `ApiProvider` 与公共 `compat` 函数不得直接暴露 Native Capability；任何没有 Effective Binding 的 Compat Native 调用必须 Unsupported，不能绕过 `Models.applyAuth()`。

### Session Entry

- 保留现有 `type: "compaction"` 作为 Local Compaction，不增加模糊 Strategy 字段，不修改旧 Entry。
- 新增独立 `type: "remote_compaction"`。它至少保存 Entry ID、Parent ID、Timestamp、Operation ID、Sanitized Summary、Self `firstKeptEntryId`、Tokens Before、Usage、Provider Context Envelope 与内部 Metadata。
- Session Version 升为 4；v3 → v4 Migration 只更新 Header Version，不改写现有 Compaction Entry 的业务字段。
- `buildSessionContext` 在最新 Active Entry 是 Remote 时返回 Provider Context 和该 Entry 之后的新 Messages；不把 Sanitized Summary 送给 LLM。
- `buildPortableRawContext` 沿当前 Leaf Ancestry 构造扁平原始语义 Entry，排除所有 Local/Remote Compaction、Provider Context、Trigger、管理 Entry、Sibling 与指定 Overflow Error Entry。

### Compaction Metadata DTO

所有自动展示边界只允许使用同一个 Allowlist DTO：

- `attemptId`、`operationId`。
- `reason: manual | threshold | overflow`。
- `requestedStrategy: local | remote | auto`。
- `effectiveStrategy: local | remote`。
- `protocol`、`provider`、`model`。
- `tokensBefore`、`estimatedTokensAfter`、可公开 Usage。
- `fallbackCode` 或 `errorCode`，值只能来自内部 Sanitized Enum/Union。
- `experimental: true`，直到真实 R1 Gate 完成。

DTO 不得包含 `providerContext`、`items`、`encrypted_content`、Credential Hash、Resolved Endpoint、Provider Response Body、Request Body 或未经净化的 Provider Error Message。

### Compaction Attempt FSM

固定顺序：

1. 解析 Requested Strategy，生成 Attempt/Operation/Entry ID，冻结 Branch Head。
2. 从当前 Ancestry 构建 Portable Preparation；Overflow 时排除 Trigger Assistant Entry。
3. 调用 `session_before_compact`。
4. 处理 Hook：所有策略允许 Cancel；显式 Remote 收到 Custom Result 时失败；Local/Auto 可接受 Custom Local Result。
5. 执行 Capability/Binding/Capacity Preflight。
6. 执行 Remote 或 Local；Auto 每 Attempt 最多一次 Remote 与一次 Local Fallback。
7. Adapter 结果完整验证；再次确认 Branch Head 未变化且未 Abort。
8. 进入 Append Phase。此后禁止 Fallback 或 Reissue。
9. 以 Operation ID 幂等 Append。Append 抛错时 Reload Session 并查询 Operation ID：存在即视为 Committed；不存在则返回 Indeterminate/Failed，禁止自动重试。
10. 从已提交 Session 重建 Context，通过 Agent 的原子 `replaceContext()` 一次替换 Messages 与 Provider Context。
11. 发出 Sanitized Post Event；再由现有 Queue 逻辑 Flush 消息。

“Commit 前零状态变化”仅指 Compaction-owned Session/Agent State。Extension Hook 可能有第三方副作用，系统不承诺回滚；Hook 后必须重验 Frozen Branch Head，并在文档中要求 Hook 保持只读。

### Native Request/Result/Error Allowlist

- `NativeCompactionPublicOptionsMap` 由 `model.api` 判别，Options 自身不增加 `api` 字段。`openai-responses` 与 `openai-codex-responses` 分别从现有 `OpenAIResponsesOptions`、`OpenAICodexResponsesOptions` 精确 `Pick`，共同只允许 `signal/apiKey/fetch/headers/timeoutMs/maxRetries/maxRetryDelayMs/env/onPayload/onResponse/sessionId/cacheRetention/reasoningEffort/reasoningSummary/serviceTier`；Codex 额外允许 `textVerbosity`。Native Compact 不使用 `toolChoice/transport/temperature/maxTokens/websocketConnectTimeoutMs/metadata`；所有 Azure 专属字段、未知字段、`binding/credentialScopeHash/providerContext/requestId` 和内部品牌一律拒绝。
- Runtime Validator 必须按 `model.api` 校验字段值而非只检查键：Public `reasoningEffort` 为 `minimal/low/medium/high/xhigh/max`，Summary 为 `auto/detailed/concise/null`；Codex Effort 额外允许 `none`，Summary 额外允许 `off/on`，`textVerbosity` 为 `low/medium/high`；两者 `serviceTier` 为 `auto/default/flex/scale/priority/null`。`cacheRetention` 为 `none/short/long`；`apiKey/sessionId` 若存在必须非空；Headers 为 `string|null` 值记录，Env 为 string 值记录；Timeout/Retry Delay 为有限非负数，Retry Count 为非负安全整数；Signal、Fetch 与 Callback 必须为对应运行时类型。
- 当前 Native 首版只支持 `openai-responses` 与 `openai-codex-responses`，并由两个 Adapter 各自实现；`azure-openai-responses` 和 Custom API 在 Capability 阶段返回 Unsupported，不得通过开放索引或透传额外字段扩展。`onPayload` 只能修改 Adapter 公开 Payload，Adapter 必须在回调后重新执行协议 Schema 校验，且回调不得接触 Binding、Scope Hash 或内部 Request Brand。
- `NativeCompactionProviderRequest<TApi>` 必须且只允许 `model/context/options/binding/providerContext?`：`model` 是有效 `Model<TApi>` 快照；`context` 的类型是 `Omit<Context, "providerContext">`；顶层 `providerContext` 是唯一经过验证的 Provider Context 真相源；`options` 精确取自 `NativeCompactionPublicOptionsMap[TApi]`；`binding` 是当前 Effective Request 的标准化 Binding。额外键和未登记 Request 均拒绝。
- Models 新建 Request 时深复制并冻结 Plain Data：Model、Canonical Context、Headers/Env、Binding 与 Provider Context；Request 和 Options 容器冻结。`AbortSignal`、Fetch、`onPayload`、`onResponse` 仅检查运行时类型并保留引用，不遍历、不复制、不冻结调用方拥有的对象。私有 `WeakSet` 只登记最终冻结的 Request 对象本身。
- Capability 签名固定为：`compact(request) -> Promise<NativeCompactionResult>`；`canConsumeProviderContext(request) -> Promise<boolean>`；`resolveNativeCompactionEndpoint(model, options) -> NativeCompactionEndpoint`。`false` 只表示 Adapter 正常判定一个已验证 Context 不可消费；非法输入或 Provider 异常必须 reject 固定 Sanitized Error，不能返回 `false` 吞掉故障。
- `NativeCompactionResult` 只允许必需的 `providerContext` 和可选的 `usage` 两个顶层键；Envelope 只允许 `format/version/binding/items`，顶层 `protocol` 属于额外字段并必须拒绝，唯一协议来源是 `binding.protocol`；Binding 只允许 `provider/api/model/endpoint/format/protocol/credentialScopeHash`。
- `NativeCompactionUsage` 必须且只允许 `inputTokens`、`outputTokens`、`totalTokens` 三个必需字段；每个字段都是有限、非负、安全整数。Adapter 负责把 SDK Usage 规范化为这三个字段，SDK 的 details 和其他附加字段不得进入公共 Result。
- 非空字符串约束只作用于 Binding 的 `provider/api/model/endpoint/format/protocol/credentialScopeHash` 等结构判别字段，不作用于 `items` 内普通字符串；Canonical Item 中的空文本是合法 JSON。危险键固定为 `__proto__`、`prototype`、`constructor`，所有结构对象和 `items` 全深度的 own string key 都必须拒绝这三个名称。
- Native Error 条件唯一映射：API/Capability/Resolver/稳定 Auth Subject 缺失为 `unsupported`；调用方 Context、Envelope/Binding 结构、Canonical Item、Trigger、Usage 或额外字段非法为 `invalid_context`；结构合法但当前 Effective Binding 不一致为 `binding_mismatch`；已知输入/输出容量超限为 `capacity`；Envelope format/version/protocol 不支持、Provider Response Schema/JSON/SSE 协议非法为 `protocol`；Abort 为 `aborted`；其他 HTTP/Auth/Network/Timeout 或 Provider 执行失败为 `provider_error`。
- `createNativeCompactionError(code)` 只接受 Code，不接受 message/cause/details。固定消息表为：`unsupported` → `Native compaction is not supported.`；`invalid_context` → `Native compaction context is invalid.`；`binding_mismatch` → `Native compaction context binding does not match the active provider.`；`capacity` → `Native compaction input exceeds the supported capacity.`；`protocol` → `Native compaction protocol is incompatible.`；`aborted` → `Native compaction was aborted.`；`provider_error` → `Native compaction provider request failed.`。Error 没有 `cause`、原始异常字段或自定义序列化字段。
- 普通 Stream 在没有 `providerContext` 时保持旧路径；存在非空 `providerContext` 但没有 Consumer 时必须在任何 Fetch 前返回 Sanitized Unsupported。任何 Native 失败不得把 Provider 返回值、异常文本或 Context 原文写入 Error。

## 策略与失败语义

| 请求 | Native 可用 | Native 结果 | 行为 |
|---|---:|---|---|
| `local` | 任意 | 不适用 | 只执行 Portable Local |
| `remote` | 否 | 不适用 | 失败；不 Fallback |
| `remote` | 是 | 任意失败 | 失败；不 Fallback |
| `auto` | 否 | 不适用 | 执行 Portable Local，记录 Unsupported |
| `auto` | 是 | 成功 | 提交 Remote |
| `auto` | 是 | 非 Abort、非 Stale、Append 前失败 | 最多一次 Portable Local Fallback |
| `auto` | 是 | Abort、Stale 或已进入 Append Phase | 不 Fallback |

默认正常使用采用 `auto`：OpenAI/Codex Native 不可用、Binding 已失效或请求失败时，从本地 Raw Ancestry 调用 Pi 现有 Local Compaction，并且只有 Local 成功后才替换 Active Context。显式 `remote` 仅用于用户明确要求远端或测试远端能力的场景，失败不得伪装成本地成功；无论何种策略，原始本地会话记录都不得删除。

Codex V2 → Legacy 不是 Local Fallback。只有 HTTP Status 属于 400/404/422，且结构化 `code/message/param` 同时明确表达 “unsupported/unknown feature” 和 `compaction_trigger` 或 `remote_compaction_v2` 时，才允许尝试 Legacy。Bare 404、`model_not_found`、401/403、429、5xx、Network、Timeout、Malformed JSON、SSE Early Close 或 0/2 Compaction Item 均不得尝试 Legacy。真实 R1 发现新 Error Shape 时只能新增精确 Fixture 与 Allowlist，不得放宽为 Status-only。

- 唯一目标：让 `Models.compact()`、`Models.canConsumeProviderContext()` 和带 Provider Context 的普通 Stream 共用唯一 Preflight；所有 Auth、Endpoint、Protocol、Scope 和 Request Brand 均在发网前确定。

- 实现步骤：
  1. 在 `OAuthAuth` 增加可选且统一为 Async 的 Provider-owned `getStableSubject(credential)`，并由 `lazyOAuth` 完整转发。Auth Resolution 使用私有 `WeakMap<AuthResult, EffectiveAuthMetadata>` 保存 `api_key` 或 `oauth { finalCredential, previousCredential?, getStableSubject }`；任何 `AuthResult` Clone 都必须调用私有传播 Helper，禁止向可枚举 `AuthResult` 添加字段，也禁止从任意扩展字段或 Access Token 猜 Subject。发生 Refresh 时分别解析前后 Subject；任一缺失、空值或不相等均为 `unsupported`，回调抛错净化为 `provider_error`。
  2. 区分调用方 Public Options 与 Auth 后 Internal Resolved Options。`openai-responses` 只允许最终 Effective API Key Auth，并以最终发送的完整 Key 计算 `SHA-256("api-key:" + key)`；`openai-codex-responses` 只允许 Effective OAuth Auth，调用方提供 `apiKey` 必须在任何 Auth/Provider Fetch 前拒绝，不能覆盖 `toAuth()` 生成的 Access Token。OAuth Scope 只计算 `SHA-256("chatgpt-account:" + stableSubject + ":" + Provider.id)`；header-only、稳定 Subject 缺失或刷新前后 Subject 漂移均为 `unsupported`。SHA-256 使用 Web Crypto `crypto.subtle.digest`。
  3. 固定 Preflight 顺序为：`signal check → model.api 白名单与 Capability 三件套运行时收窄（不读 Auth）→ raw Options/Context Validate+Clone → applyAuth → abort check → 只保留 defined own key 的 Effective Options → Effective Options/Model 再校验并冻结 → Scope Hash → Endpoint Resolver → Binding → Envelope Exact Match → 冻结 Request → 私有 WeakSet Brand 登记`。缺 Capability、Custom/Azure、部分三件套、非法 raw getter 或非法 own `undefined` 必须在 Credential Read/OAuth Refresh/Provider Fetch 前失败。
  4. 实现唯一私有 Provider Narrowing Helper：先按 `model.api` 白名单判别，再一次性把 Erased Provider 收窄为该 API 的 `NativeCompactionProviderCapabilities<TApi>`；业务调用点禁止散落 `as never`。Resolver 可在品牌登记前调用；`compact`/Consumer 只能接收最终冻结并登记的 Request。

  6. 让 Adapter/Provider 提供 `resolveNativeCompactionEndpoint`。Models 对 Resolver 原始字符串只做结构校验：首版只接受 `http/https` 绝对 URL，不允许 username、password、fragment 或控制字符；保留原始字符串和语义 Query，不 Normalize、不删除 Query、不猜测 Azure/Codex 路由。Resolver 返回的 `endpoint/protocol` 原样进入 Binding，并在 Result 中逐字段 Exact Match。
  7. Preflight 输出必须同时包含已收窄 Capability、冻结 branded Request，以及仅供普通 Stream 使用、重新附加已验证顶层 `providerContext` 的冻结 Stream Context。普通 `stream/streamSimple` 在 Context 没有 Provider Context 时完全保持旧路径；存在 Provider Context 时先跑同一 Preflight 和 Consumer，Consumer 为 `true` 后必须用该冻结 Model/Options/Context 快照 Dispatch，禁止回到原始可变对象。Envelope mismatch 必须在调用 Consumer 前结束。
  8. `Models.compact()` 使用实际 Canonical Context；`Models.canConsumeProviderContext(model, providerContext, options)` 使用固定冻结空 Context `{ messages: [] }`；带 Context 的普通 Stream 使用其实际 Canonical Context，三者只允许调用同一 Preflight。Models 构造的 Request `context` 必须剥离 `providerContext`，顶层 verified `providerContext` 是唯一真相源。

  2. `compact` 与 Consumer 首行调用私有品牌断言，之后只读取冻结 Request。基于现有 `buildRequestBody()` 构造请求，但 `includeSystemPrompt=false`；Input 固定为 `已验证的旧 providerContext.items → 本次 Context 转换后的 Message Items → 唯一末尾 {"type":"compaction_trigger"}`。旧 Context 只允许“零个或多个保留的 User Message，最后恰好一个 Compaction Item”，不得含旧 Trigger；末尾 Trigger 不得进入返回的 Canonical Envelope。
  3. Compact 固定 `store:false`、`stream:true` 并走 HTTP SSE，不使用 WebSocket、`previous_response_id` 或普通 Stream Cache Continuation；其余 `instructions/tools/reasoning/text/service_tier/prompt_cache_key` 继续复用现有 Codex Body 语义。现有 Tool Schema 可能含 TypeBox 非枚举内部字段，因此先对 Adapter 构造结果执行一次 `JSON.stringify`/`JSON.parse` 语义投影，再交给严格 Plain JSON Validator；Callback 看到和实际 Wire 一致的深冻结 Plain Data，而不是含内部 Descriptor 的对象。
  4. Native V2 Payload 顶层只允许 `model/store/stream/instructions/input/tools/tool_choice/parallel_tool_calls/temperature/reasoning/service_tier/text/include/prompt_cache_key`；必须拒绝额外键、Symbol、Accessor、非枚举字段、自定义 Prototype、Cycle、Proxy Trap 与非 JSON 值。`model` 必须等于冻结 Request Model；`store` 必须为 `false`；`stream` 必须为 `true`；`input` 必须为 Array；`instructions`、`prompt_cache_key` 为可选 String；`tools`、`include` 为可选 Plain JSON Array；`tool_choice` 只允许 `auto/none/required`；`parallel_tool_calls` 为 Boolean；`temperature` 为有限 Number；`reasoning` 只允许可选 String `effort/summary`；`service_tier` 必须属于当前 `OpenAICodexResponsesOptions.serviceTier` Union；`text` 只允许 `verbosity: low/medium/high`。`onPayload` 不看到 Binding、Credential Scope 或品牌；回调后重验完整 Allowlist、旧 Canonical Prefix 深度不变、唯一末尾 Trigger 不变且无 `previous_response_id`，失败时 0 Provider Fetch。
  5. Header 在调用方 Header 合并后强制加入 `remote_compaction_v2`，保留其他逗号分隔 Beta Feature，但调用方不能删除或重复该项；复用现有 Bearer、`chatgpt-account-id`、Originator、Session、Zstd、Timeout 与 Fetch。初版不虚构 Pi 当前没有来源的 Codex 内部 `x-codex-turn-metadata`。
  6. SSE Collector 直接读取 `parseSSE()` 的原始事件，不能经过会把 Incomplete 归一成 Completed 的普通 `mapCodexEvents()`：允许并忽略额外的非 Compaction `response.output_item.done`；只收集 `type:"compaction"` 且 `encrypted_content` 为非空字符串的 Item；只以结构正确的 `response.completed` 成功终止，且全流 Compaction Count 恰好为 1。Malformed JSON/Schema、0/2 Compaction、空密文都不能返回 Partial Result。
  7. Retry 上限固定为“首次尝试 + 最多 2 次重试”；调用方 `maxRetries` 只能把重试数降到 0 或 1，不能提高到 2 以上。纯分类表固定为：Fetch Reject、Body Reader Transport Failure、无 Terminal Early Close 和 `response.incomplete` 可重试；HTTP 429/500/502/503/504 可重试，但 429 Body 命中现有 Terminal Usage/Quota 分类时不重试；SSE `type:error` 或 `response.failed` 只有结构化 Code `server_error/internal_server_error/rate_limit_exceeded` 可重试。`context_length_exceeded` 映射 `capacity`；`insufficient_quota/usage_not_included/invalid_prompt/bio_policy/cyber_policy/server_is_overloaded/slow_down`、未知 Code、Abort、Malformed、0/2 Item 与空密文不重试。该白名单保留 Baseline 已验证的 `server_error` 重试，同时不按自由文本猜测未知 Error。每次重试复用同一冻结 Body；`onPayload` 只执行一次，`onResponse` 每个取得 HTTP Response 的 Attempt 各执行一次；退避等待前后都检查 Abort。
  8. Canonical Result 只从已验证 Request Input 和唯一 Compaction Output 构造：删除末尾 Trigger；排除 Developer/System/Assistant/Tool/Old Compaction/Trigger，只保留真实 User Message；固定使用 Codex Baseline 的 `64_000` 文本 Token Budget，Token 估算为 `ceil(UTF-8 byte length / 4)`。从最新向最旧保留，选择每个 User Message 时用 `max(全部 Text Token 之和, 1)` 计费，Image/Audio 自身不另扣 Token；再恢复原顺序。某条 Message 超出剩余预算时按 Content 原顺序处理：Text 在预算充足时完整保留并扣费，不足时使用 `remaining * 4` Byte Budget 做 Unicode Code Point 安全的 Middle Truncation，然后剩余归零；后续 Text 丢弃，Image/Audio 始终原样保留。Middle Truncation 的左侧 Byte Budget=`floor(total/2)`、右侧为余数，只在完整 UTF-8 Code Point 边界切割，并插入 `…K tokens truncated…`，其中 `K=ceil((原 UTF-8 Bytes - Byte Budget)/4)`；测试精确断言奇偶预算、中文/Emoji、Marker、首尾与 Content 顺序。最后追加唯一新 Compaction Item。
  9. 新增唯一 SDK-free JWT Account Parser，同时供 OAuth 与 Adapter 使用。`getStableSubject(finalCredential)` 必须从 `finalCredential.access` 解析非空 `chatgpt_account_id`；若持久化 `credential.accountId` 存在，还必须与 Token Subject 完全相等，否则返回 `undefined`。Adapter Header 只能使用同一 Parser 的结果，不重新计算 Scope Hash，也不把短期 Access Token 本身当身份。Stored A + Token B、Malformed Token、Missing Subject 均在 Provider Fetch 前 `unsupported`；刷新前后同 Subject 可继续。
  10. 普通 Codex Stream Replay 前仍走 ATOM-01C Exact Binding Preflight 与一次性私有 WeakSet Handoff。携带 `providerContext` 时必须禁用 WebSocket/Cache Continuation，使用完整 HTTP SSE Input：`保留 User Items → Compaction Item → 新 Messages`，且不得追加 Trigger；Consumer 返回 false 映射 `unsupported`。无 `providerContext` 时保持现有普通 Transport 选择和 Payload 形状。
  11. 固定异步顺序：`品牌断言 → Abort → 构造/冻结 Wire Body → 初验 → await onPayload → Abort → 终验 → 每个 Attempt Fetch → Abort → await onResponse → Abort → 每次 SSE reader.read() 后 Abort → Collector/Result Validate → Abort → Return`。Fetch 后 Abort 时不得调用 `onResponse` 或读取 Body；`onResponse` 中 Abort 后不得读取 Body；未知 Callback/Fetch/Reader 异常必须净化。Adapter 结果返回后只保留非负安全整数 `inputTokens/outputTokens/totalTokens`，忽略 SDK/Codex Details；缺 Usage 合法。固定 Native Error 不含 Response Body、Event、Token、Account ID、Endpoint、Canonical Item 或原始 Provider Message。
- 接口、数据与错误契约：已 Abort 或重试等待中 Abort 为 `aborted`；非法请求/回调/事件/结果结构为 `protocol`；合法 Envelope 但 Binding 不等由 Models 返回 `binding_mismatch`；可判定的上下文/使用量上限为 `capacity`；认证/网络/HTTP/Terminal Failed 为净化后的 `provider_error`。Early Close、0/2 Compaction、Invalid JSON 不返回 Partial Result。Provider `NativeCompactionError` 保留固定 Code，未知异常统一净化。
- 边界与异常：Text 截断不能破坏 JSON Item 或 Unicode；User Image/Audio 保留，Tool/Assistant/Developer/System 与旧 Compaction/Trigger 排除；同账号 Token Refresh 兼容，不同 Account/Model/Endpoint 拒绝且 0 Provider API Fetch。OAuth Refresh 属 Auth 网络，不计入“0 Provider Fetch”。
